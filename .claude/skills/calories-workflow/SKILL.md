# Рабочий цикл Calories

Проект на SwiftUI + SwiftData, семь языков, тесты обязательны. Ниже — то,
на чём здесь спотыкаются, и почему это важно. Не правила ради правил:
каждый пункт стоил кому-то потерянного часа.

## Перед коммитом

Прогнать **весь** набор, а не только новые тесты:

```bash
xcodebuild -scheme Calories -destination 'platform=iOS Simulator,id=<UDID>' test 2>&1 \
  | grep -E "✘ Test |XCTAssert|error:|Test run with|TEST (SUCCEEDED|FAILED)" | sort -u | head -6
```

Причина: UI-тесты завязаны на навигацию. Переименовал вкладку, переставил
кнопку, заменил `NavigationLink` на показ поверх — и падает тест, который
про эту правку вообще не думал. Это не помеха, а обратная связь: если
UI-тест упал, значит пользовательский путь изменился, и надо решить,
изменился ли он намеренно.

Отдельно проверить, что не осталось непереведённых строк (см. ниже).

## Переводы

Язык разработки — русский, ключ в каталоге и есть русский текст. Переводить
надо на **все семь**: `en, es, pt, fr, de, ar, he`. Каталог —
`Calories/Localizable.xcstrings`.

Забытая строка не падает и не подчёркивается — она просто показывается
по-русски в английском интерфейсе, и это замечает пользователь, а не ты.

Проверка после правки:

```bash
python3 - <<'PY'
import json, re, os
d=json.load(open('Calories/Localizable.xcstrings', encoding='utf-8'))
have={k for k,v in d['strings'].items() if v.get('localizations')}
pats=[r'String\(localized:\s*"([^"]+)"\)', r'Text\("([^"]+)"\)', r'Label\("([^"]+)",',
      r'Button\("([^"]+)"\)', r'Section\("([^"]+)"\)', r'\.navigationTitle\("([^"]+)"\)',
      r'Picker\("([^"]+)"', r'DatePicker\("([^"]+)"']
missing={}
for root,_,files in os.walk('Calories'):
    for f in files:
        if not f.endswith('.swift'): continue
        s=open(os.path.join(root,f), encoding='utf-8').read()
        for p in pats:
            for x in re.findall(p, s, flags=re.S):
                if re.search(r'[А-Яа-яЁё]', x) and x not in have and '\\(' not in x:
                    missing.setdefault(x, f)
print("БЕЗ ПЕРЕВОДА:", len(missing))
for k,v in sorted(missing.items()): print(f"  {v:26} {k[:70]!r}")
PY
```

Исключение: названия языков в списке выбора («Русский») остаются на своём
языке намеренно.

## Тесты

**Не сравнивай локализованный текст.** Набор идёт на английской локали,
поэтому `String(localized: "Левый")` вернёт `"Left"`, и сравнение с русским
литералом провалится. Проверяй то, что от языка не зависит: вердикт вместо
подписи, раскладку по родам вместо самих слов, распределение по категориям
вместо названий продуктов.

**Делай UI-тесты идемпотентными.** Данные приложения переживают прогоны:
поле, в которое уже вводили «40», при повторном прогоне получит «4040», а
тап по уже выбранному пункту ничего не сделает. Приводи состояние к
известному в начале теста. Для замеров есть отладочный флаг
`ui_test_reset_measurements`, он чистит только их.

**Не сноси приложение ради чистых данных.** `simctl uninstall` стирает
заодно пройденный онбординг и выбранный язык, и человек потом получает
чужой экран. Пользуйся флагом сброса.

**Списки ленивые.** То, что ниже экрана, в дереве элементов отсутствует —
прокручивай до элемента перед проверкой.

## Проверка глазами

Правку интерфейса надо увидеть, а не только собрать. Но:

- координаты симулятора — **в точках**, а не в пикселях скриншота
  (скриншот примерно в 2.3 раза крупнее);
- скриншот иногда отдаёт подвисший кадр перехода — если увиденное
  противоречит коду, перепроверь, а не переписывай код наугад;
- когда глазами не выходит, надёжнее написать UI-тест: он детерминирован.

## Секреты

Ключи API в репозиторий не кладём. `FoodDataCentralService` читает ключ
сначала из `UserDefaults` устройства, потом из Info.plist — так его можно
держать вне гита. Перед коммитом убедись, что ключа нет в исходниках.

## Оформление коммита

По-английски, в повелительном наклонении. Заголовок — что изменилось для
пользователя, не перечень файлов. Тело объясняет **почему**: какая проблема
была и почему выбрано именно это решение. Если правка чинит собственную
регрессию — так и написать. В конце — сколько тестов стало.

Пример:

```
Make food rows take the first tap

Converting the rows from navigation links to plain-styled buttons cost
them their hit area: a .plain button in a list is only hittable over its
own content, so a tap on the empty part of a row went nowhere.

The rows now use the contentShape plus tap-gesture pattern the rest of
the app already uses for tappable list rows.

1 new test, 129 in total.
```

## Ловушки этого проекта

Стоили времени, повторять не надо:

- **`.plain`-кнопка в списке** ловит тап только по своему содержимому.
  Для тапабельной строки — `.contentShape(Rectangle())` + `.onTapGesture`.
- **Ветвление в `ViewModifier`** (вернуть `content` или
  `content.модификатор()`) пересоздаёт всё дерево вместе со стеком
  навигации — экран выбрасывает назад. Применяй модификатор всегда,
  «ничего не делать» выражай значением.
- **`.animation` на корне** по той же причине роняет навигацию: транзакция
  идёт по всей иерархии.
- **Корневой `.fontDesign` перекрывает** начертание у любого шрифта ниже,
  включая явно заданный. Показать образец шрифта внутри такого дерева нельзя.
- **Новое свойство SwiftData-модели** требует значения по умолчанию, иначе
  уже сохранённые записи не смигрируют.
- **Тернарник с опциональным замыканием** в списке аргументов вешает
  компилятор — выноси в функцию с явным типом.
- **Идентификатор доступности на строке целиком** перекрывает
  идентификаторы вложенных элементов.
