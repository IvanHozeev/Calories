# CalorieCounter

Простое приложение-счётчик калорий на SwiftUI + SwiftData (iOS 17+), без внешних зависимостей.

## Как запустить
1. В Xcode: File → New → Project → App, назвать `CalorieCounter`, интерфейс SwiftUI. Deployment target — iOS 17.0 или выше (нужно для SwiftData).
2. Заменить сгенерированные файлы `ContentView.swift` и `CalorieCounterApp.swift` на файлы из этой папки, остальные — добавить в проект.
3. Собрать и запустить.

## Что внутри
- **Models.swift** — `Macros` (белки/жиры/углеводы), `FoodEntry` (модель SwiftData — запись о приёме пищи), `MealItem` (черновая позиция до сохранения), `WeightEntry` (модель SwiftData — запись взвешивания), `DaySummary` (вычисляемая сводка по дню), `Sex`/`ActivityLevel`/`Goal`/`UserProfile` (профиль и формула расчёта целевых калорий и белка).
- **CalorieStore.swift** — состояние приложения поверх `ModelContext` SwiftData: хранит и синхронизирует записи, пользовательские продукты и записи веса; группировка по дням, суммы БЖУ, хранение и обновление профиля.
- **ProgressRing.swift** — кольцо прогресса дня.
- **MacrosRow.swift** — переиспользуемый компонент отображения Б/Ж/У.
- **FoodDatabase.swift** — `FoodItem` (модель SwiftData) + база из ~55 встроенных продуктов с калорийностью и БЖУ на 100 г (встроенные продукты не сохраняются в базу, живут только в памяти).
- **FoodQuantityView.swift** — выбор порции (в граммах) для продукта из базы, расчёт калорий и БЖУ на лету, добавляет позицию в черновик приёма пищи (не сохраняет сразу).
- **AddEntryView.swift** — экран сборки приёма пищи: выбор даты, черновой список добавленных позиций с итогом наверху (можно удалять до сохранения), быстрый ввод только калорий, подробный ручной ввод (с БЖУ), свои продукты, поиск по встроенной базе — все способы добавляют позицию в черновик, а не сохраняют сразу. Кнопка «Сохранить» внизу пишет весь приём пищи в базу **одной записью** (калории и БЖУ суммируются, название — из названий продуктов через запятую). Кнопка «+» в шапке — отдельно, для сохранения нового продукта в свою базу (с БЖУ), это не влияет на текущий черновик.
- **ProfileView.swift** — профиль: пол, вес, рост, возраст, уровень активности, цель (похудение/поддержание/набор массы), норма белка на кг веса. Считает BMR (формула Миффлина-Сан Жеора), TDEE и целевые калории/белок, при сохранении обновляет дневную цель.
- **ContentView.swift** — главный экран: кольцо, карточка БЖУ за сегодня с прогресс-баром по белку относительно цели из профиля, баннер-приглашение заполнить профиль (если ещё не заполнен) или взвеситься сегодня (если профиль уже есть, а веса за сегодня нет), статистика, список приёмов пищи с БЖУ каждой записи и удалением.
- **HistoryView.swift** — график калорий за последние 7 дней (Swift Charts) + список дней (последняя неделя показывается всегда, даже пустые дни — можно открыть и добавить записи задним числом).
- **WeeklyChartView.swift** — столбчатый график калорий с линией дневной цели; принимает произвольный список дней и заголовок, используется и в истории, и на экране веса для сравнения с калориями.
- **WeightChartView.swift** — линейный график динамики веса.
- **AddWeightView.swift** — экран быстрой записи взвешивания (вес + дата, по умолчанию сегодня, поле предзаполняется последним весом).
- **WeightView.swift** — экран веса: текущий вес, изменение за выбранный период (7/30/90 дней), график динамики веса и график калорий за тот же период рядом для визуального сравнения (дефицит/профицит vs реальная динамика), список всех записей с удалением свайпом.
- **DayDetailView.swift** — детали конкретного дня: суммарное БЖУ, список записей с удалением, кнопка «+» для добавления записи в этот день.
- **CalorieCounterApp.swift** — создаёт `ModelContainer` для `FoodEntry`/`FoodItem`/`WeightEntry` и `CalorieStore` поверх него.

## Трекинг веса
Отдельная модель `WeightEntry` (SwiftData) — по одной записи на взвешивание. Экран веса (иконка весов в шапке главного экрана) показывает:
- текущий вес и изменение за выбранный период (7/30/90 дней);
- график динамики веса;
- график калорий за тот же период — специально рядом, для визуального сравнения дефицита/профицита с реальной динамикой веса;
- список всех записей с удалением.

Если профиль заполнен, а вес за сегодня ещё не внесён, на главном экране появляется баннер-напоминание. Вес в профиле (используемый в формуле BMR) при этом не синхронизируется с журналом взвешиваний автоматически — это разные вещи: в профиле вес используется для расчёта нормы, в журнале — для отслеживания динамики. Если вес заметно изменился, стоит вручную обновить его в профиле, чтобы пересчиталась цель по калориям.

## Как считаются цели по калориям и белку
1. BMR (базовый обмен) — формула Миффлина-Сан Жеора: `10×вес + 6.25×рост − 5×возраст (+5 для мужчин / −161 для женщин)`.
2. TDEE (суточный расход) = BMR × коэффициент активности (1.2–1.9 в зависимости от уровня).
3. Целевые калории = TDEE × коэффициент цели: похудение ×0.8 (дефицит 20%), поддержание ×1.0, набор массы ×1.1 (профицит 10%).
4. Целевой белок = вес × норма г/кг (по умолчанию 1.7, можно менять в профиле).

При сохранении профиля дневная цель по калориям на главном экране автоматически обновляется на посчитанное значение (её всё ещё можно поменять вручную тапом по кольцу). Белок отслеживается отдельно — карточка БЖУ показывает потреблённое сегодня и прогресс-бар к цели.

## Хранение данных
Раньше — ручной JSON в `UserDefaults`. Теперь — SwiftData (SQLite под капотом): нормальная схема, запросы по дате через `FetchDescriptor`, не нужно перечитывать/переписывать весь массив при каждом изменении. `dailyGoal` (число) остался в `UserDefaults` — для одного значения так проще.

Важно: данные всё ещё живут в контейнере конкретной установки приложения на конкретном устройстве/симуляторе. Если пересоздать Xcode-проект с другим bundle identifier, удалить приложение перед переустановкой или сделать Erase All Content and Settings в симуляторе — это будет для системы новое приложение с пустой базой, независимо от того, UserDefaults это или SwiftData. Чтобы данные переживали переустановки и синхронизировались между устройствами, нужен отдельный шаг — SwiftData + CloudKit.

## Как работает переход на новый день
Каждая запись хранит точную дату и время. «Сегодня» — это записи, у которых `Calendar.isDateInToday` истинно; всё остальное автоматически попадает в историю. Дополнительной логики "сброса" не требуется — как только наступает полночь, вчерашние записи сами уходят в историю, а счётчик сегодняшнего дня стартует с нуля.
